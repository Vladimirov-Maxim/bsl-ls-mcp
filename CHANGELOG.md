## [0.2.0] — 2026-10-06

### Добавлено
- **`bsl_rules_check`** — проверка правок задачи по правилам проекта: шаблоны (регулярка +
  область строки) из внешнего реестра и каталог проверок кода — чтение и запись базы в цикле
  (в том числе через вызов метода модуля), форма транзакции, параметры метода, выходной
  параметр без инициализации, пустые строки без отступа, обработчики записи без
  `ОбменДанными.Загрузка`, вызов служебного интерфейса чужого общего модуля. Только строки
  задачи (`git diff -U0`; новый файл — целиком). Источник правок — git (рабочая копия или
  ревизия) или пара каталогов «эталон / копия». Без индекса LSP.
- **`bsl_task_methods`** — новые и изменённые методы задачи.
- Командная строка без демона: `bsl-ls-mcp rules-check …`, `bsl-ls-mcp task-methods …`.
- Реестр правил — внешний (`rules`, `BSL_RULES`): правило «код» ссылается на проверку по ключу
  (`реализация`), номер, уровень и текст — данные проекта. Без реестра — встроенный каталог.
  Невыполнимое правило называется в `пропущено`, а не молча пропускается.
- Гард слоёв (`tests/test_architecture.py`): правила проверки — чистые функции без диска,
  процессов и LSP; каналы MCP и командной строки друг о друге не знают.
- Настройки `BSL_RULES`, `BSL_GIT`.

### Безопасность
- git в источнике правок запускается с `--no-ext-diff --no-textconv`, без fsmonitor, с
  `safe.directory` только для проверяемого репозитория; пути вызова MCP — из разрешённых корней.

## [0.1.1] — 2026-09-30

### Исправлено
- `bsl_reindex` больше не подвешивает навигацию. Детекция готовности индекса
  полагалась только на строгий сигнал `$/progress` (конец тяжёлой фазы с тиками);
  при вырожденном реиндексе (тёплый дисковый кэш BSL LS без report-тиков, либо
  потерянный `end`) сигнал не приходил, `_watch_ready` крутился вечно, статус навсегда
  залипал в `building`, а навигация висела. Добавлен предохранитель
  (`BSL_INDEX_READY_FALLBACK`, деф. 90 c полной тишины прогресса) + отмена задач старой
  сессии при перезапуске. Строгий быстрый путь сохранён как основной.

### Удалено
- Трей-пультик (`bsl-ls-tray.exe`, `tray/`, `build-tray.ps1`, зависимости pystray/Pillow).
  Всё, что он делал, доступно без него: полный реиндекс — MCP-инструмент `bsl_reindex`,
  рестарт — штатный `Restart-Service`/`nssm`, состояние индекса — `status.json`.

### Изменено
- `install-service.ps1`: параметр `-AllowedRoots` (выставляет `BSL_ALLOWED_ROOTS`).
- Описания `bsl_definition`/`bsl_references` в `tools/list`: «символ» → «метод».

## [0.1.0] — первый публичный выпуск

### Возможности
- MCP-сервер (FastMCP) над BSL Language Server; транспорты stdio / sse / streamable-http.
- **Проверка кода** — `bsl_diagnostics` через пакетный `analyze` (без индекса):
  адресация модулем корпуса, произвольным путём (`path`) или снипетом кода (`text`);
  фильтр по severity со сводкой, drill-down по коду диагностики.
- **Навигация по тёплому индексу** — `bsl_callers`, `bsl_callees`, `bsl_definition`,
  `bsl_references`; поддержка модулей форм и команд (round-trip адресов).
- **Метрики** — `bsl_complexity` (когнитивная/цикломатическая сложность).
- **Обслуживание** — `bsl_reindex` (полный реиндекс in-place).
- Нативный бандл (PyInstaller + portable JRE), Windows-служба (NSSM) с гашением java
  через Job Object, трей-пультик со статусом индекса.

### Безопасность
- Конфайнмент `path`-режима под `BSL_WORKSPACE` + `BSL_ALLOWED_ROOTS`; отказ от `..`,
  абсолютной замены базы и UNC (защита от обхода каталога и утечки NTLM через SMB).
- Валидация сегментов доменного имени (обход каталога через имя модуля/формы).
- Привязка к не-loopback адресу требует явного `BSL_ALLOW_REMOTE=1`.
- Проверка SHA256 внешних загрузок (BSL LS jar, NSSM); опция низкоправной учётки службы,
  тайт-ACL на статус-каталог, предупреждение о слабых правах на каталог бандла.
- Требование MCP SDK `>=1.9.4` (защита от DNS-rebinding в HTTP-транспорте).
  Подробности — [SECURITY.md](SECURITY.md).

### Известные ограничения
- Только Windows (служба/скрипты/Job Object).
- Граф вызовов/ссылок — снимок индекса; новые межмодульные связи видны после `bsl_reindex`.
- `bsl_diagnostics` не выявляет «переменная/метод не определён» (нет семантики областей
  видимости — это делает синтаксический контроль конфигуратора/EDT).
- `bsl_complexity` не имеет параметра `path` (код вне индексированного корпуса не покрывает).
