## [Unreleased]

## [0.14.0] — 2026-10-20

### Изменено
- **`form.server-call-in-client-event` вменяет только добавленное задачей** (как
  повторное чтение реквизита в 0.10.0). Находка — на строке серверного вызова из правки задачи: в самом обработчике
  или глубже по клиентской цепочке (вызов добавлен во вспомогательный метод), либо на вызове
  метода, который правка задачи сделала серверным. Прежние серверные вызовы обработчика —
  контекстом: «серверные вызовы в существующем коде обработчика — строки …». Тронутый обработчик
  с унаследованным вызовом находки больше не даёт — правилу можно вернуть уровень Fail.

## [0.13.0] — 2026-10-20

### Добавлено
- **Команда `diagnostics`**: диагностики BSL LS по модулям задачи из
  командной строки — для хуков и CI. Ключи и формат ответа — как у
  `rules-check`; только строки задачи, error → Fail, warning → Warn, `ид` — код диагностики,
  исключения — из реестра; код возврата 1 при Fail. Модули задачи и описания их объектов и форм
  раскладываются во временный проект из текстов источника правок (годится и `--rev`), по нему —
  analyze: тип модуля и реквизиты формы видны. Ключ `--bsl-config`; Java по умолчанию — `jre/`
  рядом с инструментом.

### Исправлено
- **Внешняя обработка EDT в `bsl_diagnostics(path=…)`** (0.12.0): обёртка не клала
  `DT-INF/PROJECT.PMF`, без него analyze проект EDT не распознаёт — описание форм не читалось.
  Теперь `DT-INF` + `src/`; живой тест.
- analyze без отчёта (java не стартовал, упал по памяти) — ошибка, а не пустой список
  «замечаний нет».

## [0.12.0] — 2026-10-19

### Добавлено
- **`bsl_complexity(path=…)`**: любой локальный `.bsl` или каталог —
  внешняя обработка, расширение тестов, выгрузка ревизии MR. `full_name` — имя модуля 1С, где
  его можно определить (корпус, внешняя обработка/отчёт), иначе путь от `path`. Файл вне
  workspace открывается на сервере на время запроса и убирается из его контекста: одного
  `didClose` BSL LS мало — документ оставался в графе вызовов, поэтому ещё «файл удалён».

### Исправлено
- **Внешняя обработка по `path` — с описанием форм**. Объект (выгрузка
  конфигуратора или EDT) оборачивается во временную конфигурацию, и BSL LS читает `Form.xml`:
  реквизиты формы больше не «неиспользуемые локальные переменные», обработчики из описания — не
  «неиспользуемые методы». Подпись — `ВнешняяОбработка.Имя.Форма.Ф`. Формы реальных внешних
  обработок: 3 ложных `UnusedLocalVariable` и 8 `UnusedLocalMethod` → 0; 10 и 4 → 0.
- analyze по корню конфигурации подписывал файлы ссылкой на объект (`mdoRef`
  `DataProcessor.Х.Form.Ф`) вместо пути — теперь путь файла.

## [0.11.0] — 2026-10-16

### Добавлено
- **`form.assign-form-property`**: в модуле формы необъявленное имя,
  совпадающее с примитивным свойством формы, — запись в свойство, а не новая переменная
  (`Доступность = ПроверитьДоступность(…)` → «несоответствие типов» на исполнении). Находка —
  если справа объект (`Новый …`, кроме `УникальныйИдентификатор`) или имя дальше используется
  через `.`/`[`. Список свойств — настройка `свойства_формы`. На рабочей конфигурации EDT (~10 тыс. форм) — 1 находка.
- **`form.server-call-in-client-event`**: обработчик `НачалоВыбора`,
  `НачалоВыбораИзСписка`, `ИзменениеТекстаРедактирования` вызывает метод `&НаСервере` — прямо или
  через клиентские методы модуля. Привязки обработчиков — из описания формы (EDT `Form.form`,
  конфигуратор `Ext/Form.xml`) и `УстановитьДействие`. Список событий — настройка
  `события_без_серверных_вызовов`. Уровень по умолчанию Warn: на рабочей конфигурации EDT 174 находки, в том числе
  в коде поставщика, — запрет из «Примечания» статьи события стоит сверить по синтакс-помощнику.

## [0.10.0] — 2026-10-16

### Исправлено
- **Пара каталогов: строки задачи — `git diff --no-index`**, тем же
  алгоритмом, что в git-режиме. Построчное сравнение выравнивало одинаковые строки (пустые) иначе,
  и находка уходила не на добавленную строку: на реальной задаче проверка пустой строки без отступа называла 64 вместо 73 и
  пропускала добавленную пустую строку 216. Без git — прежнее сравнение.
- **Повторное чтение реквизита — находка на строке задачи**: если задача добавила первый вызов
  `ЗначениеРеквизитаОбъекта` перед существующими, находка — на нём, старые строки даны контекстом.
- **`bsl_complexity` по `Тип.Объект` — все модули объекта**: у отчёта
  возвращались только методы модуля менеджера; теперь и модуля объекта, с адресом модуля в
  `full_name`. Фильтр `function` — без учёта регистра.

## [0.9.0] — 2026-10-16

### Исправлено
- **`task-methods`: «новый» — только метод, которого нет в базе**. Метод с
  изменённым объявлением (параметры) — «изменён»; переименованный — «новый». База — версия
  файла в `base` (git) или эталон (пара каталогов).
- **Смена окончаний строк — не правка задачи**: строки задачи считаются с
  `--ignore-cr-at-eol`. Файл, отличающийся от базы только CRLF/LF, больше не даёт ни «новых»
  методов (было — 94 метода чужого файла), ни находок `rules-check` по всему файлу.
- Переименованный файл сравнивается с прежним путём (`-M`), а не считается целиком добавленным.

## [0.8.0] — 2026-10-16

### Исправлено
- **Честное сворачивание по размеру**. Уровни сворачиваются по одному с
  низшего (`hint` → `info` → `warning`), пока ответ не уместится, — а не всё, кроме `error`, разом.
  Пометка называет свёрнутые уровни и их число, показанные целиком и невыданный запрошенный
  уровень; новое поле `suppressed.folded_by_size`. Прежняя пометка «warning свёрнуты» звучала и
  тогда, когда warning не было вовсе. На общем модуле в 9 тыс. строк с `min_severity="hint"`: свёрнуты
  hint 310 и info 354, все 76 warning показаны (раньше — только 28 error).

## [0.7.0] — 2026-10-16

### Добавлено
- **Зона правок в `bsl_diagnostics`**: `lines="2660-2781"`
  (`от-до[,от-до]`, один файл цели) или `function="Метод[,Метод2]"` (границы метода от директив
  `&…` до `Конец…`, во всех модулях цели). Только диагностики зоны, все уровни, без сворачивания
  по размеру; зона названа в `источник.фильтр`. Работает в обоих источниках и для снипета.
  Замер на рабочей конфигурации EDT: метод на 460 строк в модуле на 9110 строк — 76 диагностик, 14 КБ.

## [0.6.0] — 2026-10-16

### Добавлено
- **`bsl_callers` находит вызовы по строковому имени**:
  `ДлительныеОперации.ВыполнитьФункцию(…, "Модуль.Метод")`, `ВыполнитьМетодКонфигурации`, имя в
  переменной. Литерал, целиком равный `Модуль.Метод` / `Документы.Имя.Метод`, без учёта регистра,
  вне комментариев и текста запросов. Записи со `способ: "строка"` и `строки`; вызовы из графа
  LSP — `способ: "вызов"`. На рабочей конфигурации EDT три метода общего модуля, вызываемые через
  `ДлительныеОперации` (было «0 вызывающих»), — найдены с номером строки. Поиск — ~0.9 c (`git grep` + неотслеживаемые из `git status`).

## [0.5.0] — 2026-10-16

### Добавлено
- **Переназначение уровней диагностик** (`BSL_SEVERITY_OVERRIDES`, по умолчанию
  `UnknownMember=info`). `UnknownMember` BSL LS 1.0.7 — `error` с массой ложных срабатываний
  (поля выборок, ключи структур, реквизиты регистров EDT); на уровне `error` она ломала гейт
  «ноль error» и прятала настоящие ошибки. Теперь — `info`: в `suppressed` и через
  `code="UnknownMember"`; ответ называет переназначение в `источник.переназначено`. Замер на
  рабочей конфигурации EDT: error по модулю 55→3, 193→28, 15→0, 12→6.

### Исправлено
- `build.ps1`: подсказка про системную Java — 21+, а не 17+.

## [0.4.0] — 2026-10-16

### Добавлено
- **Диагностики кода корпуса из тёплого LSP** (`module_full_name`, `path` внутри workspace),
  pull-запросом `textDocument/diagnostic`: сервер видит метаданные конфигурации. На рабочей конфигурации EDT
  исчезли ложные `UnusedLocalMethod`/`UnusedLocalVariable` в формах, появились
  `ExecuteExternalCodeInCommonModule`, `CommonModuleInvalidType`, `ServerSideExportFormMethod`,
  `UsingThisForm`, `MissingCommonModuleMethod`; модуль — 1–2 c вместо ~10 c. Пока индекс
  строится — прежний analyze, сервер прогревается в фоне. Поле ответа `источник`
  `{движок, примечание?}`; `BSL_DIAG_ENGINE=auto|lsp|analyze`.
- **Свежесть графа вызовов**: перед каждым запросом навигации и
  диагностик сервер получает правки `.bsl` с начала индексации — по `git status`/`git diff` от
  HEAD индексации, без git — обходом по mtime. Новый вызов из другого модуля виден в
  `bsl_callers` без `bsl_reindex`. Настройки `BSL_FRESHNESS`, `BSL_FRESH_MIN_INTERVAL`,
  `BSL_FRESH_SCAN_SEC`, `BSL_FRESH_OPEN_LIMIT`.
- Живой тест на настоящем BSL LS (`tests/test_lsp_live.py`, пропускается без Java 21).

### Исправлено
- LSP-режим работал без конфига проекта: BSL LS 1.0.x игнорирует `-c` у `lsp`, путь теперь
  передаётся свойством `-Dapp.configuration.path`.
- Тайм-аут LSP-диагностик больше не превращается в пустой список («замечаний нет»).

### Изменено
- `--selftest` проверяет через analyze и не прогревает индекс.

## [0.3.0] — 2026-10-07

### Добавлено
- **Проект EDT** наряду с выгрузкой конфигуратора. Формат определяется по корню
  (`Configuration.xml` / `Configuration/Configuration.mdo`); резолв имён, диагностики,
  сложность, навигация и подписи — в обоих форматах. Объект EDT (`Справочник.X`)
  проверяется без своих форм: в `analyze` уходит копия только модулей объекта.
- Проверки правок задачи в репозитории EDT: конфигурация глубже корня (`App/src/`), новый
  общий модуль распознаётся по `CommonModules/<Имя>/<Имя>.mdo`.
- База правок по умолчанию — `merge-base` с `develop` (`BSL_BASE_BRANCH`), без такой ветки —
  `HEAD`. В ответе `bsl_rules_check` — поле `база` {ревизия, как}.
- Виды метаданных: последовательность, нумератор документов, внешний источник данных,
  сервис интеграции, WS-ссылка. Модули HTTP/веб-сервисов, общих форм и общих команд.
- `install-service.ps1`: `-Config` (BSL_CONFIG), `-BaseBranch`, `-Rules`, путь к git для службы.

### Изменено
- BSL Language Server 0.29.0 → **1.0.7**; нужна **Java 21**.
- `bsl_diagnostics(path)` принимает любой локальный путь (UNC по-прежнему запрещён);
  `BSL_ALLOWED_ROOTS` остаётся только для путей проверок правок задачи.
- `base` у `bsl_rules_check`/`bsl_task_methods`/CLI по умолчанию не `HEAD`, а авто (см. выше).
- `build.ps1` собирает из активного virtualenv, если он задан (`VIRTUAL_ENV`).

### Исправлено
- Подписи диагностик устойчивы к коротким именам путей Windows (8.3).

## [0.2.0] — 2026-10-06

### Добавлено
- **`bsl_rules_check`** — проверка правок задачи по правилам проекта: шаблоны (регулярка +
  область строки) из внешнего реестра и каталог проверок кода — чтение и запись базы в цикле
  (в том числе через вызов метода модуля), форма транзакции, параметры метода, выходной
  параметр без инициализации, пустые строки без отступа, обработчики записи без
  `ОбменДанными.Загрузка`, вызов служебного интерфейса чужого общего модуля. Только строки
  задачи (`git diff -U0`; новый файл — целиком). Источник правок — git (рабочая копия или
  ревизия) или пара каталогов «эталон / копия». Без индекса LSP.
- **`bsl_task_methods`** — новые и изменённые методы задачи.
- Командная строка без демона: `bsl-ls-mcp rules-check …`, `bsl-ls-mcp task-methods …`.
- Реестр правил — внешний (`rules`, `BSL_RULES`): правило «код» ссылается на проверку по ключу
  (`реализация`), номер, уровень и текст — данные проекта. Без реестра — встроенный каталог.
  Невыполнимое правило называется в `пропущено`, а не молча пропускается.
- Гард слоёв (`tests/test_architecture.py`): правила проверки — чистые функции без диска,
  процессов и LSP; каналы MCP и командной строки друг о друге не знают.
- Настройки `BSL_RULES`, `BSL_GIT`.

### Безопасность
- git в источнике правок запускается с `--no-ext-diff --no-textconv`, без fsmonitor, с
  `safe.directory` только для проверяемого репозитория; пути вызова MCP — из разрешённых корней.

## [0.1.1] — 2026-09-30

### Исправлено
- `bsl_reindex` больше не подвешивает навигацию. Детекция готовности индекса
  полагалась только на строгий сигнал `$/progress` (конец тяжёлой фазы с тиками);
  при вырожденном реиндексе (тёплый дисковый кэш BSL LS без report-тиков, либо
  потерянный `end`) сигнал не приходил, `_watch_ready` крутился вечно, статус навсегда
  залипал в `building`, а навигация висела. Добавлен предохранитель
  (`BSL_INDEX_READY_FALLBACK`, деф. 90 c полной тишины прогресса) + отмена задач старой
  сессии при перезапуске. Строгий быстрый путь сохранён как основной.

### Удалено
- Трей-пультик (`bsl-ls-tray.exe`, `tray/`, `build-tray.ps1`, зависимости pystray/Pillow).
  Всё, что он делал, доступно без него: полный реиндекс — MCP-инструмент `bsl_reindex`,
  рестарт — штатный `Restart-Service`/`nssm`, состояние индекса — `status.json`.

### Изменено
- `install-service.ps1`: параметр `-AllowedRoots` (выставляет `BSL_ALLOWED_ROOTS`).
- Описания `bsl_definition`/`bsl_references` в `tools/list`: «символ» → «метод».

## [0.1.0] — первый публичный выпуск

### Возможности
- MCP-сервер (FastMCP) над BSL Language Server; транспорты stdio / sse / streamable-http.
- **Проверка кода** — `bsl_diagnostics` через пакетный `analyze` (без индекса):
  адресация модулем корпуса, произвольным путём (`path`) или снипетом кода (`text`);
  фильтр по severity со сводкой, drill-down по коду диагностики.
- **Навигация по тёплому индексу** — `bsl_callers`, `bsl_callees`, `bsl_definition`,
  `bsl_references`; поддержка модулей форм и команд (round-trip адресов).
- **Метрики** — `bsl_complexity` (когнитивная/цикломатическая сложность).
- **Обслуживание** — `bsl_reindex` (полный реиндекс in-place).
- Нативный бандл (PyInstaller + portable JRE), Windows-служба (NSSM) с гашением java
  через Job Object, трей-пультик со статусом индекса.

### Безопасность
- Конфайнмент `path`-режима под `BSL_WORKSPACE` + `BSL_ALLOWED_ROOTS`; отказ от `..`,
  абсолютной замены базы и UNC (защита от обхода каталога и утечки NTLM через SMB).
- Валидация сегментов доменного имени (обход каталога через имя модуля/формы).
- Привязка к не-loopback адресу требует явного `BSL_ALLOW_REMOTE=1`.
- Проверка SHA256 внешних загрузок (BSL LS jar, NSSM); опция низкоправной учётки службы,
  тайт-ACL на статус-каталог, предупреждение о слабых правах на каталог бандла.
- Требование MCP SDK `>=1.9.4` (защита от DNS-rebinding в HTTP-транспорте).
  Подробности — [SECURITY.md](SECURITY.md).

### Известные ограничения
- Только Windows (служба/скрипты/Job Object).
- Граф вызовов/ссылок — снимок индекса; новые межмодульные связи видны после `bsl_reindex`.
- `bsl_diagnostics` не выявляет «переменная/метод не определён» (нет семантики областей
  видимости — это делает синтаксический контроль конфигуратора/EDT).
- `bsl_complexity` не имеет параметра `path` (код вне индексированного корпуса не покрывает).
