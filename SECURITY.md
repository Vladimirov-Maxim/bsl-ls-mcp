# Модель безопасности

`bsl-ls-mcp` — локальный инструмент разработчика. Он даёт MCP-клиенту доступ к
статическому анализу и навигации по исходникам 1С. Ниже — как он ограничивает доступ
и как его безопасно разворачивать.

## Границы

- **Демон НЕ аутентифицирует вызовы.** Любой, кто достучится до HTTP-эндпоинта
  (`/mcp`), получает все инструменты: анализ произвольных путей под разрешёнными
  корнями, чтение строк кода, реиндекс (DoS). Поэтому по умолчанию сервер слушает
  **только loopback** (`127.0.0.1`).
- **Конфайнмент путей.** `bsl_diagnostics(path=...)` принимает путь только внутри
  `BSL_WORKSPACE` или явно перечисленных `BSL_ALLOWED_ROOTS`. Пути с `..`, абсолютная
  замена базы и **UNC** (`\\host\share`) отвергаются — последнее закрывает утечку
  NTLM-хэша сервисного аккаунта через исходящий SMB.
- **Валидация имён.** Сегменты доменного имени (`Тип.Модуль.Метод`, формы, команды)
  проверяются регуляркой: только буквы/цифры/`_`. Разделители пути и точки внутри
  сегмента исключают обход каталога через имя модуля.

## Развёртывание

- **Не выставляйте порт в сеть.** Если это действительно нужно, поставьте перед демоном
  обратный прокси с авторизацией и TLS. Привязка к не-loopback интерфейсу заблокирована
  без явного `BSL_ALLOW_REMOTE=1` — и через ENV (`BSL_MCP_HOST=0.0.0.0`), и через флаг
  (`--host 0.0.0.0`). Анти-DNS-rebinding SDK (валидация заголовка `Host`) — **не**
  аутентификация: `Host` тривиально подделывается прямым HTTP-клиентом, поэтому единственная
  реальная защита открытого эндпоинта — обратный прокси.
- **Учётка службы.** По умолчанию NSSM ставит службу под `LocalSystem`. Для снижения
  привилегий задайте `install-service.ps1 -ServiceAccount "NT SERVICE\bsl-ls-mcp"`
  (виртуальный аккаунт службы) или доменную сервисную учётку.
- **Каталог бандла.** Служба под SYSTEM запускает `bsl-ls-mcp.exe`. Не размещайте бандл
  в каталоге, куда могут писать непривилегированные пользователи (иначе подмена exe →
  выполнение под SYSTEM). Рекомендуется `%ProgramFiles%`; `install-service.ps1`
  предупреждает о слабых ACL.
- **Статус-файл.** `install-service.ps1` создаёт `%ProgramData%\bsl-ls-mcp`, забирает
  владение каталогом (Администраторы) и ставит явный ACL (SYSTEM/Администраторы — полный
  доступ, остальные — только чтение); если каталог уже существует как reparse point
  (junction/симлинк) — установка прерывается (защита от pre-plant). Если демон поднят БЕЗ
  install-скрипта, рантайм создаёт каталог сам (`mkdir`) без этой защиты — для боевого
  развёртывания под SYSTEM ставьте службу через `install-service.ps1`.

## Целостность загрузок

Сборка и установка скачивают внешние артефакты и **проверяют SHA256** перед
использованием: BSL Language Server jar (`build.ps1`) и NSSM (`install-service.ps1`).
