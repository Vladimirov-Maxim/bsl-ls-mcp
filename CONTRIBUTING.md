# Contributing

Спасибо за интерес к проекту. Сразу честно: проект развивается по остаточному принципу
(см. «Статус проекта» в [README](README.md)) — issue и pull request я могу подолгу не
смотреть, и это нормально. Если правка нужна вам здесь и сейчас — самый быстрый путь
форкнуть и допилить под себя (MIT это позволяет). Присланные PR приветствую и посмотрю
по возможности, без обещаний по срокам.

Если всё же делаете PR: небольшие правки — сразу PR; для крупных изменений заведите issue
с описанием подхода, чтобы не делать работу впустую.

## Требования

- **Windows** — рантайм завязан на Windows (служба через NSSM, `.ps1`/`.cmd`, Job Object).
  Юнит-тесты без java/LSP, но оперируют путями CR-выгрузки в Windows-раскладке —
  прогоняйте их на Windows (там же гоняется CI).
- Python 3.10+.
- Java 17+ (или portable JRE в бандле) — для реального запуска BSL Language Server.

## Локальная разработка

```bash
python -m pip install -e ".[dev]"   # mcp + pytest + ruff
python -m pytest                    # юнит-тесты (чистая логика, без java)
python -m ruff check .              # линт
```

`server/bsl-language-server-*-exec.jar` в репозитории **нет** — он скачивается из
upstream-релиза при сборке (`build.ps1`). Для запуска демона положите jar в `server/`
или соберите бандл.

## Стиль

- Форматирование/линт — `ruff` (`line-length = 100`). Прогоняйте `ruff check .` перед PR.
- Тесты — `pytest`, добавляйте покрытие для новой чистой логики (`domain/`).
- Комментарии — по делу («почему», а не «что»); без дизайн-дневника.

## Архитектура (кратко)

Слои `domain` (модели, порты, резолвер, маппер) → `application` (инструменты, MCP-сервер)
→ `infrastructure` (LSP-клиент по stdio, analyze-CLI). Подробности — в
[README_full.md](README_full.md).

## PR

- Одна логическая правка на PR, осмысленное описание.
- CI (`ruff` + `pytest`) должен быть зелёным.
